# 实现要点

本文记录实现中的关键约束及其成因；修改相关模块前，请先确认这些约束仍然成立。

## 选区与标注

- **选区只在主进程存一份**（虚拟屏 DIP 坐标），光标位置一律取 `screen.getCursorScreenPoint()`，避免多个窗口各自计算坐标而导致不一致
- **松手不直接完成**：`phase` 从 `selecting` 进 `adjusting` 才出 8 向手柄、才浮出工具条，此阶段选区可实时调；Enter / 双击 = 复制，点「钉住」才进贴图；手柄几何集中在 `shared/selection.ts`，主进程用它判定当前操作属于调整手柄 / 整体移动 / 重新框选，遮罩用它绘制手柄与鼠标样式 —— 两侧必须共用同一套几何，否则会出现手柄可见却无法拖动的不一致
- **手柄只从完整选区上取**，跨屏选区中被本屏裁剪掉的角由对应屏的遮罩绘制，本屏不以裁剪后的矩形角代替真实手柄
- **工具条只挂一块屏**：选区中心所在屏渲染浮条（`toolbarDisplayId`），其余屏收到的广播里带同一个 `activeTool`，跨屏画图用的是一套工具
- **指针分流在遮罩里先于编辑器注册**：手型工具 / 点在选区外 → 转主进程调选区（`stopImmediatePropagation`），绘图工具且选区内 → 交由编辑器绘制。注册顺序颠倒会导致编辑器抢占调整选区的按下事件
- **打字时主进程让出 Enter / Esc**：文字输入框开合走 `overlay:editState`，否则 `before-input-event` 会将 `Enter`（提交文字）误判为**复制**、将 `Esc`（取消文字）误判为**取消截图**
- **遮罩阶段的标注存本屏 DIP**，确认 / 导出时才换算成图像像素；贴图画布 backing = 图像像素、CSS 尺寸 = 窗口 − 四边留白，`devicePixelRatio` 不参与换算，拖到别的 DPI 屏不错位

## 抓屏与 DPI

- **每块屏的抓屏都发生在它自己的遮罩窗口创建之前**，并 `setContentProtection(true)`，避免把自己截进图里
- **抓屏回读实际尺寸**：`thumbnailSize` 只是请求值，比例用 `thumbnail.getSize()` 反推，不直接用 `display.scaleFactor`
- **抓屏分批 + 窗口复用**：光标所在屏优先完成，其余屏并行抓取、就绪一块显示一块（不等待全部就绪）；遮罩窗口按 `displayId` 缓存，收起时仅 `hide()` 并释放位图，下次以 `reload()` 复用 —— 首帧就绪超时因此由 6s 降至 2.5s。**确认选区前会等待其余屏抓取完成**，否则拼接结果中该屏对应的区域为空
- **每屏一个遮罩窗口**，而不是一个窗口横跨多屏 —— 跨混合 DPI 时，单窗的 `devicePixelRatio` 语义不明确，且会受到 `WM_DPICHANGED` 抖动影响
- **拼接时对「边」四舍五入再相减**：相邻两屏共享的那条 DIP 边代入的是同一个表达式 → 同一个整数 → 零缝隙。写成 `起点 + round(宽 × 比例)` 会在边界差 1 像素
- **输出比例取相交屏的 max**：用主屏比例会不可逆地丢掉高 DPI 屏的文字细节（放大不丢数据，缩小才丢）

## 遮罩渲染

- **遮罩画布必须 `setTransform` 到 CSS 像素，不能用单位矩阵**：backing store 是 `cssWidth × dpr`，单位矩阵仅覆盖左上 `1/dpr` 的区域 —— 在 125% / 150% 缩放的屏幕上会出现空白区域，选框位置亦不正确
- **遮罩每帧重画全部标注**：当前未启用离屏缓存，每帧回放全部标注；标注数量较多且包含马赛克时若出现帧率下降，可将标注层拆分为独立画布

## 贴图窗口

- **贴图 = 图像 + 四边阴影留白**（`shared/pin-layout.ts` 的 `PIN_SHADOW_PAD` ≤16px）：`computePinLayout` 按该侧屏幕的剩余空间计算留白（贴边为 0，该侧已无空间绘制阴影），随 `pin:boot` 下发；渲染进程按同一 padding 让出画布位置。窗口必须设为 `transparent` —— 阴影绘制在窗口自身的留白区域内，窗口不透明时会被背景覆盖
- **拖贴图使用原生 `app-region: drag`**：整扇窗口即为拖拽区，由系统原生处理，避免主进程 16ms 轮询 `setBounds` 的开销，跨 DPI 边界也不会因窗口重标定而错位
